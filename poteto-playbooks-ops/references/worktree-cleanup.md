### Worktree and simulator cleanup

1. Snapshot and audit. Record `df -h /`, then audit every worktree with `git worktree list` as the source of truth for paths (never hand-typed, per **principle-encode-lessons-in-structure**: a hand-typed path misses copies that live elsewhere). Classify each worktree by size, age, merge state, uncommitted work, PR state, and the newest session that touched it, then suggest a bucket. The transcript scan is slow, so background it.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (**principle-prove-it-works**). Get that set from the user and cross-check every candidate. A worktree the user had pinned wins over any "safe to delete" classification.
3. Verify usage before deleting. For anything you doubt, fan subagents out to read the transcripts via `session_search` and report whether the chat is pinned or ongoing and which worktrees it touches (**principle-guard-the-context-window**, transcripts are bulk). A pinned chat can spawn arena and repro trees into sibling worktrees via background subagents, and those are in use even when their names never surface elsewhere. Pick each subagent's reasoning level for the job, per poteto-mode's Subagents section.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. Per poteto-mode's Autonomy section, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers, where the platform has an equivalent: delete unavailable or old virtual device instances, clear derived-data/build caches, and clear package manager caches the user has not said to keep.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
